## 1. 目的と方針

- URL を与えると、rcg ファイルをダウンロードして再生できるようにする。
- GitHub のリポジトリにあるログの一覧を出し、選んで再生できるようにする。
- archive.robocup.info のログの一覧も出せるようにする。ただし、2026-11-22 の時点でサイトにつながらないので、GitHub を先に作り、archive は後にする (ユーザ、2026-11-22)。
- QtNetwork はすでに必須の依存 (UDP、TCP の接続に使っている) なので、`QNetworkAccessManager` を使えば新しい依存は要らない。

## 2. 現状 (develop 5affd90)

- ログはファイルのパスからしか開けない。File > Open Game Log (`MainWindow::openGameLogFile()`、main_window.cpp:2145) → `openGameLogFile( const QString & )` (1759 行。`QFile::exists` が前提) → `openGameLogFileImpl()` (1859 行) → `loadGameLogFile()` (`src/game_log_file.cpp`)。
- コマンドラインの位置引数 (options.cpp:1597) はローカルのパスとして扱い、起動の 100 ms 後に開く (main_window.cpp:191)。
- 読み込みは GUI のスレッドで同期して行う。`RCGHandler` が 500 ms 後に進捗のダイアログを出す (中止のボタンなし)。
- gzip は、libdeflate があればメモリの上で展開する (`inflateWithLibdeflate`、game_log_file.cpp の無名の名前空間)。zlib は `gzopen(path)` でファイルからしか読めない。パーサ自体はメモリからも読める (`rcss/rcg/parser.h`)。
- `QNetworkAccessManager` はどこも使っていない。Qt6 の TLS のプラグイン (OpenSSL) は手元にある。
- ウィンドウへのドラッグ & ドロップはない (`dragEnterEvent`/`dropEvent` はコメントアウト)。最近開いたファイルの一覧もない。

### 2.1 外部のサイト (2026-11-22 に確かめた)

**GitHub (`rcsoccersim/RoboCup2026`)**
- 既定のブランチは `main`。`logs/Finals/`、`logs/GroupA/`〜 の下に `*.rcg.gz` と `*.rcl.gz` がある。全 313 件のうち、名前に rcg を含むものが 144 件。
- `GET https://api.github.com/repos/rcsoccersim/RoboCup2026/git/trees/HEAD?recursive=1` (未認証): 200、約 85 KB の JSON で全ファイルが返る (`truncated` は false)。`REF` に `HEAD` を使える。`ETag` が付く。
- 未認証の上限は 60 回/時 (`x-ratelimit-limit: 60`)。`If-None-Match` で 304 が返っても、残りの回数は減った。
- ファイルの実体: `https://raw.githubusercontent.com/rcsoccersim/RoboCup2026/HEAD/logs/Finals/<名前>.rcg.gz` が 200 で返る (`application/octet-stream`、約 4.8 MB)。このリポジトリは Git LFS を使っていない (`.gitattributes` は `logs/ export-ignore` だけ)。
- ファイル名の形: `YYYYMMDDhhmm-左のチーム_得点-vs-右のチーム_得点.rcg.gz`。PK 戦があれば `_得点_PK の得点` (例 `202607050025-FRA-UNIted_0_4-vs-NexusPrime_0_2.rcg.gz`)。チーム名に `-` と `_` が入ることがある (例 `RoboTech_Coach_base_0`、`FC-AIT_2`)。

**archive**
- `archive.robocup.org` (ユーザが最初に書いた名前。誤り): HTTPS は TLS の誤り (`tlsv1 unrecognized name`)。HTTP は Nginx Proxy Manager の既定のページ。
- `archive.robocup.info` (正しい名前): HTTPS も HTTP も接続できない。

### 2.2 rcssmonitor-web の実装 (移植の元)

- `test/unit/fetch-log.test.ts`: 上の関数の単体テスト (移植する)。
- `docs/protocol.md`: GitHub の各 URL の振る舞いの表。
- ブラウザの制約 (CORS、mixed content) は、デスクトップのアプリには関係ない。

### 3.2 設計上の判断 (Claude。段階の初めにユーザが確認する)

| # | 内容 | 理由 |
|---|---|---|
| S1 | ダウンロードしたファイルはディスクに置き、既存の `openGameLogFile( path )` で開く。パーサと読み込みの仕組みは変えない | zlib はファイルからしか読めない。読み込みの経路を 1 つに保つ |
| S2 | リダイレクトは `QNetworkRequest::NoLessSafeRedirectPolicy` で追う (明示する) | Qt5 の既定は追わない。https から http への転送は追わない |
| S3 | `http` と `https` 以外の URL は拒む。ユーザ名とパスワードのある URL も拒む (web 版と同じ) | 意図しないスキームを読まない |
| S4 | ダウンロードの大きさに上限を設ける (既定の値は段階 1 で決める。1 試合は gzip で数 MB) | 誤った URL で巨大なファイルを読まない |
| S5 | GitHub への要求の `User-Agent` は `rcssmonitor/VERSION` とし、個人の情報は入れない | GitHub は `User-Agent` を求める |
| S6 | GitHub の一覧はディスクにキャッシュし、ユーザの「再読み込み」か、一定の時間 (例 1 時間) の後にだけ取り直す | 未認証は 60 回/時で、304 でも回数が減るため |
| S7 | ダウンロードしたファイルはパーサにとって信頼できない入力なので、壊れたファイルで落ちないことをテストで確かめる (パーサは 3D 表示の計画の Phase 2 で頑健にした) | 外部のファイルを読むため |

### 3.3 段階の初めに決めること

- **ダウンロードの置き場所 (段階 1)**。推奨: `QStandardPaths::CacheLocation` (例 `~/.cache/rcssmonitor/logs/`) の下に、URL ごとに置く。同じ URL は、前に最後までダウンロードできていれば再利用する。キャッシュを消す操作 (ダイアログのボタン) を用意する。もう 1 つの案は、一時ファイルに置いて閉じたら消すもの (再利用はしない)。
- **ローカルのファイルのドラッグ & ドロップ (段階 1)**: URL のドロップと一緒に、ローカルのファイルのドロップも足すか。
- **ダウンロードしたログの保存 (段階 1)**: 「別名で保存」を用意するか (キャッシュを選んだなら、場所を開く操作で足りるか)。
- **一覧の列と絞り込み (段階 2)**: 日時、チーム、得点、大きさ、ディレクトリ。チーム名での絞り込み。
- **既定のリポジトリ (段階 2)**: `rcsoccersim/RoboCup2026` のほかに足すものがあるか (2026-11-22 の時点で、rcsoccersim の Organization で名前が RoboCup で始まるのは RoboCup2026 だけ)。

## 4. 設計

### 4.1 段階 1: URL から開く

- メニュー File > Open Game Log from URL...: URL を入れるダイアログ。最近の URL を覚えたコンボボックス (設定に保存)。GitHub のファイルのページの URL も受け付ける。
- コマンドライン: 位置引数が `http://` か `https://` で始まれば URL として開く (`rcssmonitor https://…/game.rcg.gz`)。
- ウィンドウへの URL のドロップ (`setAcceptDrops`、`dragEnterEvent`、`dropEvent`)。
- `src/log_url.{h,cpp}` (新規): web 版の `parseLogUrl`、`githubRawUrl`、`githubLfsUrl`、`lfsPointerSize`、`logNameFromUrl` を C++ (QUrl) に移す。純粋な関数にして単体テストする。
- `src/log_downloader.{h,cpp}` (新規): `QNetworkAccessManager` で 1 つの URL をダウンロードする `QObject`。
  - 進捗 (`downloadProgress`)、中止 (`QNetworkReply::abort`)、HTTP の誤り (状態コードと理由)、ネットワークの誤り、TLS の誤り。
  - 最初の応答が LFS のポインタなら、media.githubusercontent.com から読み直す (ポインタの `size` を進捗の全体に使う)。
  - 大きさの上限 (S4)。`Content-Length` が上限を超えれば読む前にやめる。
  - `QSslSocket::supportsSsl()` が偽なら、https の URL で、TLS が使えない理由と対処 (OpenSSL の入れ方) を出す。
  - 書き出しは一時的な名前に書いてから、最後に名前を変える (途中で止めたファイルを再利用しない)。
- `MainWindow`: ダウンロードの間は `QProgressDialog` (中止のボタンつき) を出す。終わったら `openGameLogFile( path )` で開き、ウィンドウの題名にはログの名前 (`logNameFromUrl`) を出す。別のログを開いたり、サーバに接続したりしたら、ダウンロードをやめる。

### 4.2 段階 2: GitHub のログの一覧

- メニュー File > Browse Game Logs...: ログの一覧のダイアログ (`src/log_browser_dialog.{h,cpp}`、新規)。
  - 左にリポジトリの一覧 (既定 `rcsoccersim/RoboCup2026`。ユーザが `owner/repo` または `owner/repo@ref` を足し、消せる。設定に保存)。
  - 右にログの木: ディレクトリ (Finals、GroupA…) ごとにまとめ、列は日時、左のチーム、得点、右のチーム、大きさ。チーム名で絞り込む欄。
  - ダブルクリックか「開く」で、段階 1 のダウンロードに渡す。
  - 「再読み込み」で一覧を取り直す。
- `src/github_log_index.{h,cpp}` (新規):
  - `GET https://api.github.com/repos/OWNER/REPO/git/trees/REF?recursive=1` (`REF` の既定は `HEAD`)。`Accept: application/vnd.github+json`。
  - 応答の JSON (`QJsonDocument`。QtCore にある) から、`type` が `blob` で名前が `.rcg` か `.rcg.gz` で終わるものを取り出す (パス、大きさ)。`truncated` が真なら、一覧が欠けていることを出す。
  - ファイルの URL は `https://raw.githubusercontent.com/OWNER/REPO/REF/PATH`。
  - 一覧のキャッシュ (S6): `CacheLocation` の下に JSON と取得の時刻を置く。
  - 誤り: 403/429 で `x-ratelimit-remaining: 0` なら、`x-ratelimit-reset` から解除の時刻を出す。404 はリポジトリかブランチがない。
- `src/log_file_name.{h,cpp}` (新規): ファイル名の解釈 (純粋な関数)。
  - `^(\d{12})-(.+)-vs-(.+)\.rcg(\.gz)?$` で日時と左右に分け、左右それぞれを `^(.*?)_(\d+)(?:_(\d+))?$` (チーム名は最短一致) でチーム名、得点、PK の得点に分ける。
  - 例: `FRA-UNIted_0_4` → `FRA-UNIted`、0、4。`RoboTech_Coach_base_0` → `RoboTech_Coach_base`、0。
  - 解けなければ、名前をそのまま出す。

### 4.3 段階 3: archive.robocup.info (保留)

- サイトにつながるようになってから始める。それまでは本書の状態に「保留」と書いておく。
- 一覧の取り方を、汎用の「ディレクトリの一覧 (Apache や nginx の autoindex の HTML)」の源として作り、段階 2 のダイアログの源の 1 つにする (GitHub の源と同じインタフェース)。
- ログが `.tar.gz` などにまとめられていれば、展開の方法 (自前の tar の読み込み、または別の依存) をそのときに決める。
- 公開の状態、URL の形、自動のアクセスについての決まり (robots.txt など) を、始める前に確かめる。

### 4.4 段階 1 の実装 (2026-11-24)

4.1 を、次のように実装した。計画から決めたことも書く。

- `src/log_url.{h,cpp}` (新規。QtCore だけ): 状態を持たない static だけのクラス `LogUrl` (D7)。web 版の `parseLogUrl` を `LogUrl::parse` (`QUrl` の StrictMode。http と https だけ、ホストが要る、ユーザ名とパスワードのある URL は拒む。誤りの理由を返す) に、`githubRawUrl`、`githubLfsUrl`、`lfsPointerSize` をそのままの名前で、`logNameFromUrl` を `LogUrl::name` に移した。足したもの: `LogUrl::isUrl` (コマンドラインとドロップで、URL かローカルのパスかを見分ける)。
- `src/log_cache.{h,cpp}` (新規。QtCore だけ): ディレクトリを持つクラス `LogCache` (D7)。`pathOf` (キャッシュの `DIR/KEY/NAME`。KEY は URL の SHA-1 の先頭 16 桁。NAME はログの名前をファイル名に使える形にしたもの。ファイルの名前がログの名前になるので、窓の題名とコピーの保存にそのまま使える)、`contains`、`size`、`clear`、`defaultDir` (`QStandardPaths::CacheLocation/logs`、`~/.cache/rcssmonitor/logs`)。メインウィンドウが既定の場所の `LogCache` を持ち、ダイアログに渡す。
- 段階 1 の初めの版 (d56fad4) では、これらを `log_url.h` のグローバル関数にしていた。ユーザの指摘で、上の 2 つのクラスに作り直した (D7)。
- `src/log_downloader.{h,cpp}` (新規): `QNetworkAccessManager` で 1 つの URL を落とす `LogDownloader`。
  - 書き出しは `QSaveFile` で行う (計画の「一時的な名前に書いてから名前を変える」を、Qt の仕組みで行う。同じ URL を 2 つの rcssmonitor が同時に落としても混ざらない)。
  - リダイレクトは `NoLessSafeRedirectPolicy` (S2)、最大 10 回。`User-Agent: rcssmonitor/版` (S5)。
  - 大きさの上限 200 MB (S4、D6): `Content-Length` が超えれば本文の前に、なければ読んだ量が超えたときにやめる。LFS のポインタの `size` が超えるときも、実体を読まない。
  - データが 30 秒来なければ時間切れ (`setTransferTimeout`。Qt 5.15 以上)。その旨の文で知らせる。
  - LFS のポインタなら、`reply->url()` (リダイレクトの後の URL) を `githubLfsUrl` で読み替えて読み直し、ポインタの `size` を進捗の全体にする。読み替え先はテストのために差し替えられる (`setLfsResolver`)。
  - 進捗は、本文を読むたびに自分で出す (`QNetworkReply::downloadProgress` は、届くたびには出なかった)。
  - https で TLS が使えなければ (`QSslSocket::supportsSsl()`)、OpenSSL を入れるか http を使うよう知らせる。
  - 失敗は `start()` が戻った後に知らせ、`abort()` や次の `start()` の後には知らせない。
- `src/open_url_dialog.{h,cpp}` (新規): File > Open Game Log from URL のダイアログ。最近の URL (編集できるコンボボックス)、URL でないときの理由 (ダイアログに赤で出し、閉じない)、キャッシュの場所 (ホームは `~`) と大きさ、Clear Cache のボタン。
- `MainWindow`:
  - File メニューに「Open Game Log from URL...」(Ctrl+Shift+O) と「Save a Copy of Game Log...」(Ctrl+Shift+S) を足した。
  - URL は、キャッシュにあればそこから開き、なければ `QProgressDialog` (Cancel つき。大きさが分かれば何 MB 中何 MB かを出す) を出して落とし、落とし終えたら `openGameLogFile( path )` で開く (S1)。失敗は理由を添えてメッセージボックスで知らせる (`--auto-quit-mode` なら終わる)。進み具合のダイアログはモーダルにしない (モーダルな `QProgressDialog` は `setValue()` の中でイベントを処理し、そこでダウンロードが終わってダイアログを閉じ、その後の呼び出しで落ちた)。開くことと失敗の知らせは、`LogDownloader` の呼び出しから抜けた後に行う (`QTimer::singleShot( 0 )`。ログを読むこともメッセージボックスもイベントを処理するため)。別のログを開いたとき、サーバにつないだとき、次の URL を開いたときは、ダウンロードをやめる。
  - コマンドラインの位置引数が http:// か https:// で始まれば URL として開く。
  - ドロップ (D4): 最初の URL がローカルのファイルなら開き、http か https の URL なら落とす。URL のテキストのドロップも受ける。ローカルのファイルは拡張子を問わない (開けなければ、ファイルの選択で開いたときと同じく誤りを出す)。3D 表示は別の窓 (`QOpenGLWindow`) なので、その窓のドラッグとドロップを、メインウィンドウのイベントフィルタで同じ処理に回す。
  - コピーの保存 (D5): 開いているログのファイルを、そのまま (圧縮されていれば圧縮されたまま) 写す。ログを開くと使えるようになり、サーバにつなぐと使えなくなる。キャッシュを消した後でファイルがなければ、その旨を知らせる。
- `Options`: 最近の URL (最大 10。設定の `[GameLog]` の `recent_urls`)。URL を開いたときにすぐ書く (`writeRecentLogUrls()`。終了時には書かない)。
- テストの HOME に、キャッシュの置き場所 (`XDG_CACHE_HOME`) も足した (ユーザのキャッシュに触らない)。

### 2026-11-24: 段階 1 の見直し (ユーザが確かめて)

- ユーザが確かめた: 例の URL を Open すると Segmentation Fault で落ちた。起動し直して同じ URL (キャッシュにある) は開けた。Clear Cache の後はまた落ちた。ファイルマネージャとブラウザからのドロップは動くが、ブラウザからのドロップも、初めてのダウンロードでは落ちた。Save Game Log As で保存できた。名前は、保存ではなくコピーなので、コピーと書くほうがよいのではないか。
- 原因: 進み具合のダイアログをモーダル (`Qt::WindowModal`) にしていた。モーダルな `QProgressDialog` は `setValue()` の中でイベントを処理する。そこでダウンロードの終わりが届くと、ダイアログを閉じて (`M_download_dialog` を空にして) ログを開き、`setValue()` から戻った後の `setLabelText()` が空のポインタを使って落ちた。キャッシュから開くときは進み具合を出さないので落ちなかった。テストでは、ログが小さく途中の進み具合が出なかったので見つからなかった。ログを 2 回に分けて返すテスト (`openUrlInParts`) で再現した (3 回とも Segmentation Fault)。
- 直したこと: ダイアログをモーダルにしない。進み具合の文を先に、`setValue()` を最後にし、ダイアログを `QPointer` で見張る。落とし終えたログを開くことと失敗の知らせは、`LogDownloader` の呼び出しから抜けた後に行う (4.4)。新しいテストは、直す前は落ち、直した後は通った。
- 名前: ユーザが「Save a Copy of Game Log...」に決めた (D5)。メニュー、関数 (`saveGameLogCopy`)、メッセージ、テスト、README、NEWS、ChangeLog を直した。
- 確かめたこと: 3 つの CMake のビルドで警告はなく、`ctest -j8` をそれぞれ 3 回走らせて、64 個がすべて通った。autotools (Qt5) のビルドも警告なしで通った。
- この後: ユーザがもう一度確かめる (段階 1 の完了条件)。その後、コミットとプッシュ、CI。
