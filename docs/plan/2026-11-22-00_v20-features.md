## 1. 目的と範囲

rcssmonitor 20.0.0 の公式リリースの前に、次の機能を足す (版は 20.0.0-beta.1 にしてあるが、まだリリースしていない。`docs/dev/release.md` §0)。

| # | 機能 | 区分 | 計画 |
|---|---|---|---|
| F1 | 配色 (ライト/ダーク) を選べる (soccerwindow2 と同じ) | 必須 | 本書 §A |
| F2 | アイコンを XPM ではなく PNG で持つ (soccerwindow2 と同じ方法) | 必須 | [2026-11-22-01_icon-redesign.md](2026-11-22-01_icon-redesign.md) |
| F3 | GNOME のデスクトップから検索して起動できる | 必須 | 本書 §B |
| F4 | プレイモードが変わるときに審判の笛を鳴らす | あると嬉しい | 本書 §C |
| F5 | URL を与えて rcg をダウンロードして再生する。GitHub と archive のログの一覧 | あると嬉しい | [2026-11-22-02_remote-logs.md](2026-11-22-02_remote-logs.md) |
| F6 | 画面に描かれている内容を、連番画像または動画として出力する | あると嬉しい | [2026-11-22-03_frame-export.md](2026-11-22-03_frame-export.md) |

- 計画書は機能の大きさで分けた。小さい 3 つ (F1、F3、F4) は本書に、大きい 3 つ (F2、F5、F6) は単独の計画書にした。
- 本書には、全体の順序とブランチ、機能をまたぐ決定、リリースまでの流れも書く。

### 2.2 機能をまたぐ設計上の判断 (Claude。各段階の初めにユーザが確認する)

| # | 内容 | 理由 |
|---|---|---|
| S1 | Qt Multimedia は任意の依存にする。笛 (`QSoundEffect`、Qt5 と Qt6) と、動画の試作 (`QVideoFrameInput`、Qt 6.8 以上) が使う。見つからなければ、その機能なしでビルドできる | WebSockets (`ENABLE_WEBSOCKET`) と同じ扱い。最小の環境 (Qt 5.15、Qt 6.2) でもビルドを保つ |
| S2 | 任意の依存の形は `ENABLE_WEBSOCKET` にそろえる: CMake は `option()` + `find_package(... QUIET)` + `cmake-config.h.in` の `#cmakedefine HAVE_*`、見つからなければ `message(WARNING)`。autotools は `AC_ARG_ENABLE` + `AC_CHECK_HEADER` + `AC_DEFINE` + `AM_CONDITIONAL` | 既存の形 (`CMakeLists.txt` の WebSockets、`configure.ac` の `--enable-websocket`) |
| S3 | 新しい設定は `~/.rcssmonitor.conf` (`Options`、QSettings の INI) に足す。`Options::writeSettings(bool all)` (options.cpp:868) は MainWindow と Monitor の群を `all` のときしか書かないので、そこに足す設定は `if ( all )` の外で書く。ただし、終了時に書く設定はコマンドラインで与えた値も保存される。コマンドラインの値を保存しない設定 (配色。U7) は、終了時には書かず、メニューで選んだときにすぐ書く | 足した設定が保存されない不具合を防ぐ |
| S4 | 設定ダイアログのタブは、なるべく増やさない。増やすなら `test_config_dialog.cpp` のタブの一覧 (287、417 行) も直す | テストがタブの一覧を固定している |
| S5 | 動かして試すときは `HOME=$(mktemp -d)` で起動し、ユーザの `~/.rcssmonitor.conf` を書き換えない | 3D 表示の計画書 §0.1 と同じ |
| S6 | CI (`.github/workflows/ci.yml`) と `docs/build.md` (依存パッケージの表、CMake と configure のオプション) を、依存を足す機能のブランチで更新する | 依存が増えたことを文書と CI に漏らさない |

## §A 配色 (ライト/ダーク)

### A.1 現状 (develop 5affd90)

- 配色を選ぶ仕組みはない。View > Window Style で Qt のスタイル (QStyle) を選べるだけ。
- 選んだスタイルは保存されない: `MainWindow::changeStyle()` (main_window.cpp:2436) が `M_window_style` を更新しない。既定値の `"plastique"` は Qt5/Qt6 にないので、起動時の `QApplication::setStyle( M_window_style )` (167 行) は失敗し、プラットフォームのスタイルのままになる。
- ツールバーのアイコンは XPM またはコードで描いた形を、`QPalette::ButtonText` の色で塗り直している (`src/tool_icon.cpp` の `tintIcon`、`src/toolbar_icons.cpp`)。パレットが変わると `MainWindow::updateToolIcons()` (1470 行) で塗り直す。
- フィールドの描画 (2D と 3D) は QPalette に依存しない。色は `Options` の設定 (Color タブ) か、コードに書いた色。
- パレットに依存するところ: ビューの重ね (`M_view_stack`) の背景を黒にしている (1103 行。`test_view_switch.cpp` が確かめる)、サイクルの欄の誤りの赤 (1588〜1599 行)、設定ダイアログの範囲外の数値の赤 (`markNumber`、config_dialog.cpp:1731)、人型パックの出典の誤りの色 (`color: #c03030;`、2725 行)、ツールチップの印 (`tooltip_marker.cpp`、`WindowText`)。

### A.2 方針 (soccerwindow2 の実装を移植する)

soccerwindow2 (`../../rctools/soccerwindow2`。コミット 7e87a9c、8a15c38。計画書 `docs/plan/2026-11-19_qt6-cmake-migration.md` の Phase 5) と同じにする。

- `src/ui_palette.{h,cpp}` (新規): `UIPalette::light()`、`UIPalette::dark()`。Qt 6.5 以上の Fusion のパレット (`qt_fusionPalette()`) と同じ色を手で組む。Qt5 と Qt6 で同じ見た目になる。元: `soccerwindow2/src/qt/ui_palette.cpp`。
- `src/ui_style.{h,cpp}` (新規): `QProxyStyle`。ツールバーの押された (checked) ボタンを、ハイライトの色の半透明の角丸で描く。暗い配色で押された状態が見づらいため。元: `soccerwindow2/src/qt/ui_style.cpp`。
- `Options`: `ui_color_scheme` = `system` | `light` | `dark` (既定 `system`)。コマンドライン `--ui-color-scheme {system,light,dark}`。メニューで選んだときにだけ保存し、コマンドラインで与えた値は保存しない (soccerwindow2 と同じ)。保存は `[MainWindow]` の `ui_color_scheme` に、メニューで選んだときにすぐ書く (U7。`Options::writeUIColorScheme()`)。`Options::writeSettings` は、設定ファイルを作るとき (`all`) にだけ既定値を書く。
- メニュー: View > UI Color Scheme > System / Light / Dark。排他の `QActionGroup`。Window Style の隣に置く。
- 適用: `QApplication::setPalette()`。System は、MainWindow を作るときに取った `QApplication::palette()` (テストで暗いデスクトップをまねられる)。Qt のスタイルを変えたら、配色を当て直す (`setStyle` がパレットを戻すため)。
- 暗い配色で見直す: A.1 のパレットに依存するところ、選手の型のダイアログ、設定ダイアログの Color タブの一覧。フィールド (2D と 3D) の色と 3D の HUD は変えない (soccerwindow2 と同じ)。
- 確かめること: Qt 6.5 以上で System を選んでいるとき、実行中にデスクトップの配色を切り替えたら追従するか。追従しなければ、どこまで対応するかをユーザと決める。 → この環境 (Qt 6.4.2) では確かめられない (A.6)。
- Window Style が保存されない不具合 (A.1) も直す (U8): 既定値を空 (プラットフォームの既定) にし、メニューで選んだスタイルを `M_window_style` に入れて、窓を閉じるとき (`MainWindow::writeSettings`) に保存する。保存した名前のスタイルがないとき (古い版が書いた `plastique` など) は、プラットフォームのスタイルにして、名前を消す。

### A.4 テスト

- 3 つの選択でパレットが変わる。System は偽のパレットを使う。
- メニューの選択が排他で、選んだものが保存される。コマンドラインの値は保存されない。
- スタイルを変えた後も配色が保たれる。
- 既存の `test_toolbar` のアイコンの塗り直しのテストは、アイコン (F2) で書き直すまでそのまま通ること。

実装したテスト (`test/test_ui_color_scheme.cpp`。2026-11-22):

- 明るいパレットと暗いパレットの色、`isDark`、誤りの色のコントラスト (4.5:1 以上)。名前と配色の変換 (知らない名前では変えない)。
- 既定は System で、デスクトップのパレット (MainWindow を作る前に設定した偽の暗いパレット) になり、メニューの System に印が付く。スタイルは `UIStyle` で包まれる。
- メニューの 3 つ: 印は 1 つだけ、アプリとウィンドウのパレットが変わり、`[MainWindow]` の `ui_color_scheme` にすぐ保存される。
- スタイルを変えても配色が保たれる。選んだスタイルは窓を閉じるときに保存され、次の窓 (次の起動) で使われる。保存した名前が使えないとき (`plastique`) は、プラットフォームのスタイルになり、名前が消える。
- `UIStyle`: 押されたボタンの外周がハイライトの色になり、大きさは変わらない。ツールバーのボタンと、MainWindow の実際のボタン (ツールバーの中の QFrame の Loop)。ツールバーの外のボタンは強調しない。
- 誤りの印: サイクルの欄と、出典のような文字が、配色を切り替えると新しい配色の色で付け直される。誤りでない欄は配色に従う。設定ダイアログの数値の欄すべてが配色に従う。Color タブの見本に灰色の枠がある。
- 起動とコマンドライン: テストのプログラムを子プロセスとして、rcssmonitor と同じ順 (Options が設定ファイルを読み、コマンドラインを解析し、終了時に設定ファイルを書く) で動かす。保存した値が読まれる、コマンドラインの値が優先される、コマンドラインの値は終了時に保存されない、知らない値では変わらない (警告を出す)、設定ファイルがないときは `system` で作られる。
- `test_config_dialog.cpp`: 出典の誤りを、スタイルシートではなく文字の色 (`UIPalette::errorText`) で確かめるように直した。

### A.6 実装 (2026-11-22)

- `src/ui_palette.{h,cpp}` (新規): 配色の列挙 `UIColorScheme` (System、Light、Dark) と名前の変換 (`camera_mode.h` の `GrassMode` などと同じ形)。`UIPalette::light()`、`dark()` (soccerwindow2 と同じ色)、`of( scheme, system )`、`isDark( palette )` (アイコン (F2) も使う)、誤りの色 `errorText()`、`errorBase()`、誤りの印 `markWrongField()`、`markWrongText()`、`updateWrongMarks()`。
- `src/ui_style.{h,cpp}` (新規): soccerwindow2 の `UIStyle`。計画からの変更: 強調するボタンの条件を「親がツールバー」から「祖先 (同じ窓の中) にツールバーがある」に広げた。rcssmonitor のボタンはツールバーの中の QFrame に並んでいて、soccerwindow2 の条件では強調されなかった (offscreen の画像で分かった)。
- `Options`: `ui_color_scheme` (U7)、`--ui-color-scheme`、`writeUIColorScheme()`。
- `MainWindow`: View > UI Color Scheme (System、Light、Dark。Window Style の下)、`applyUIColorScheme()` (`init()`、メニュー、スタイルの変更の後に呼ぶ)、Window Style の保存 (U8)。`init()` は、保存したスタイル (なければ今のスタイル) を `UIStyle` で包む。
- 暗い配色での見直し (A.1 の各所):
  - サイクルの欄と、設定ダイアログの数値の欄 (`markNumber`): 誤りの色を消すときに `setPalette( QApplication::palette( w ) )` でその時の色をすべて固定していたため、配色を切り替えても前の色のまま残った。設定ダイアログは、表示を更新するたびにすべての数値の欄でこれを呼ぶので、すべての欄が残った。`UIPalette::markWrongField()` で、誤りのときは Base の色だけを、誤りでないときは何も設定しないようにした。誤りの欄は、配色が変わったときに `MainWindow::changeEvent` (`updateWrongMarks`) で、新しい配色の色で付け直す。
  - 人型パックの出典の誤りの色: スタイルシートの `#c03030` (暗い背景で 2.3:1) をやめ、`markWrongText()` で配色に合わせた赤にした (明るい配色で #c03030、4.9:1。暗い配色で #ff7070、4.8:1)。
  - 設定ダイアログの Color タブの色の見本: 白は明るい配色で、黒は暗い配色で背景に溶けていたので、灰色 (128, 128, 128) の枠を付けた。
  - ビューの重ねの黒い背景 (`Window` だけを設定しているので配色に従う)、ツールチップの印、選手の型のダイアログ、設定ダイアログのほかのタブは、そのままで問題がなかった (offscreen で書き出した画像で確かめた)。
- 分かったこと:
  - Qt6 (6.4.2) では、`QApplication::setPalette()` のパレットが、イベントを処理したときにウィジェットへ届く (Qt5 はすぐ)。実際のアプリはイベントループの中なので問題ない。テストは、選んだ後にイベントを処理する。
  - Qt のオプション `-style` は、保存したスタイルがないときだけ効く (保存したスタイルが優先)。`-style` で選んだスタイルは保存しない。
  - Qt 6.5 以上での実行中の追従 (A.2) は、この環境 (Qt 6.4.2) では確かめられない。System のときに当てるパレットは、MainWindow を作るときに取った (アプリが自分ではまだ設定していない) パレットで、Qt6 はこれをその時のテーマのパレットで補って使うので、追従する見込みである。Qt 6.5 以上の環境で確かめる機会があれば確かめる。

## §C 審判の笛

### C.1 現状と、鳴らす契機をとらえる場所

- 音を出す仕組みはない。Qt Multimedia はどこでも使っておらず、ビルドも探していない。この環境 (Ubuntu 24.04、Qt 6.4.2) には `qt6-multimedia-dev` が入っていない (パッケージはある)。
- 表示するフレームが変わると、`LogPlayer::indexUpdated(current, max)` が出る (log_player.cpp)。タイマーの再生、コマ送り、スライダーやジャンプでの移動、ライブ (`showLive`、444 行)、遅延ライブ (`showDelayedLive`、578 行)、ログを開いたときの先頭への移動のすべてで出る。
- フレーム i のプレイモードは `DispHolder::dispCont()[i]->pmode_` (`rcss::rcg::PlayMode`、`rcss/rcg/types.h:60`)。`DispHolder::playmode()` は最後に読んだモードで、表示しているモードではない。
- 通知なしに番号が動くところ: `LogPlayer::setLiveMode()` (478 行)、`DispHolder::trimLiveFrames()` (disp_holder.cpp:261。古いフレームを捨てて番号がずれる)、`clear()`。
- `DispHolder::handlePlayMode` に繋ぐのは誤り: ログ全体を読むときにも呼ばれ、ライブでは表示ではなく受信の時点になる。

### C.2 鳴らす条件

- `LogPlayer::indexUpdated` に繋ぎ、表示するフレームのプレイモードを、前に見たモードと比べる。
- ログの再生: 1 つ進んだとき (`current == prev + 1`。タイマーの再生とコマ送り) にだけ鳴らす。ジャンプ、スライダー、戻る、先頭へ、では鳴らさず、覚えているモードだけを更新する。
- ライブと遅延ライブ: 1 回の更新で複数のフレームが進むことがあるので、(prev, current] のフレームを調べ、遷移があれば 1 回だけ鳴らす (複数あれば最も強い笛)。
- ログを開いたとき (main_window.cpp:1861 の `M_disp_holder.clear()` のあたり)、接続したとき (1983 行)、`setLiveMode()`、`trimLiveFrames()` の後は、覚えているモードを消す (または番号ではなくサイクルで覚える)。
- 速い再生で笛が重ならないよう、鳴っている笛を止めてから次を鳴らす。
- 3D の表示は、ライブでは最大 2 サイクル遅れて描く (`LiveClock`)。笛が 3D の表示より少し先に鳴ることがあるが、許容し、記録に残す。

### C.3 プレイモードと笛 (案。段階の初めにユーザと決める)

#### C.3.1 実際のサッカーでの笛 (競技規則の指針)

IFAB の競技規則の「審判員の実践的なガイドライン」の Whistle の項 (https://theifab.com/laws/latest/guidelines/body-language-communication-and-whistle 、2026-11-22 に確かめた):

| 笛が要る | 笛は要らない |
|---|---|
| プレーを始める (前半と後半、延長の前半と後半)、得点の後 (のキックオフ) | はっきりしたゴールキック、コーナーキック、スローイン、得点で、プレーを止める |
| プレーを止める: フリーキックか PK のとき、試合を中断・中止するとき、各ハーフの終わり | 再開する: ほとんどのフリーキック、ゴールキック、コーナーキック、スローイン、ドロップボール |
| 再開する: 決められた距離 (9.15 m) を取らせるフリーキック、PK | |
| 警告・退場、負傷、交代で止めた後の再開 | |

- 笛を吹きすぎると、要るときの効き目が薄れる、とも書かれている。
- 各ハーフの終わりの笛の回数は規則にない (慣習)。

#### C.3.2 rcssserver の動き (`../rcssserver/src/referee.cpp`)

- 反則 (`foul_*`)、オフサイド、バックパス、フリーキックの反則、キャッチの反則、不正な守備では、そのプレイモードで 30 サイクル (3 秒) 止め (`AFTER_FOUL_WAIT`、`AFTER_OFFSIDE_WAIT` など)、最後の 5 サイクル (`CLEAR_PLAYER_TIME`) で守備側の選手をボールから離し (`clearPlayersFromBall`)、それから `free_kick_*` か `indirect_free_kick_*` に変える。
- つまり、反則の後は「止める (反則のモード)」と「距離を取らせてから再開させる (フリーキックのモード)」の 2 つの区切りがはっきりしている。規則の指針の「フリーキックのために止める」と「決められた距離を取らせるフリーキックの再開」(どちらも笛が要る) に当たる。
- スローイン、コーナーキック、ゴールキックなどは、`play_on` から直接そのモードになり、モードが変わったときに選手をボールから離す (`FreeKickRef::playModeChange`)。止める区切りと再開の区切りが分かれていない。
- ゴールキーパーのキャッチの後の `free_kick_*` も、`play_on` から直接移る (止める笛も再開の笛もない場面)。
- ドロップボールは、`drop_ball` にしてすぐ `play_on` に戻す (`Referee::awardDropBall`。PK 戦を除く)。

#### C.3.3 案 (2026-11-22。ユーザの確認待ち)

反則の後のフリーキックでは、再開の短い笛を鳴らす (反則の時点の笛と合わせて 2 回)。C.3.2 のとおり、サーバが距離を取らせてから再開するので、実際のサッカーの指針に合う。前のモードを見て、キャッチの後のフリーキックとは区別する。

| 遷移 | 笛 | 規則の指針 |
|---|---|---|
| → `kick_off_l/r` | 短い笛 | 始める、得点の後 (要る) |
| → `foul_charge_l/r`、`foul_push_l/r`、`foul_multiple_attack_l/r`、`foul_ballout_l/r`、`offside_l/r`、`back_pass_l/r`、`free_kick_fault_l/r`、`catch_fault_l/r`、`illegal_defense_l/r` | 短い笛 | フリーキックのために止める (要る) |
| 上の行のモード → `free_kick_l/r`、`indirect_free_kick_l/r` | 短い笛 (再開) | 距離を取らせるフリーキックの再開 (要る) |
| → `penalty_ready_l/r` (PK を蹴ってよい合図) | 短い笛 | PK の再開 (要る) |
| → `goal_l/r` | 長い笛 (演出) | はっきりした得点では要らない。鳴らすかを段階の初めに決める |
| → `first_half_over` | 長い笛 2 回 | ハーフの終わり (要る。回数は慣習) |
| → `time_over` | 長い笛 3 回 (試合の終わり) | 同上 |
| `play_on` → `free_kick_l/r` (キャッチの後)、→ `kick_in_l/r`、`corner_kick_l/r`、`goal_kick_l/r`、`drop_ball`、`play_on`、`before_kick_off`、`pause`、`human_judge`、`penalty_kick_l/r`、`penalty_setup_l/r`、`penalty_taken_l/r`、`penalty_miss_l/r`、`penalty_score_l/r` | 鳴らさない | 止める・再開するのに要らない |

- 前の案から変えたこと: 反則の後のフリーキックの再開に短い笛を足した。`drop_ball` は鳴らさないことにした (ドロップボールの再開に笛は要らない。rcssserver では、セットプレーが時間内に行われないときなどに、止めずにボールを落とす)。
- 得点の笛を鳴らすかと、再開の笛を設定で切れるようにするかは、段階の初めに決める。
- 延長と PK 戦の遷移の順は、段階の初めに rcssserver で確かめる。

### C.4 実装

- `src/whistle_rules.{h,cpp}` (新規): 前のモードと次のモードから笛の種類 (なし、短、長、長 2、長 3) を返す純粋な関数。単体テストで表を確かめる。
- `src/whistle.{h,cpp}` (新規): C.2 の監視と、笛を鳴らすこと。音を出す部分はインタフェースにして、テストでは偽物に替える。Qt Multimedia があれば `QSoundEffect` で鳴らす。
- 音: `tools/make_whistle.py` (新規。Python の標準ライブラリ (`wave`、`math`、`random`) だけを使う) で合成する。約 3 kHz の音を、笛の中の玉が揺らすように細かく揺らす。乱数の種を固定して、同じ WAV が作れるようにする。`resources/sounds/whistle_short.wav` と `whistle_long.wav` を作ってコミットし、`resources/sounds/sounds.qrc` で埋め込む。長い笛の 2 回、3 回は、再生の側で繰り返す。音の大きさの目安は 44.1 kHz、16 ビット、モノラル、合わせて数百 KB 以下。
- 依存: CMake のオプション `ENABLE_SOUND` (既定 ON。Qt Multimedia が見つからなければ警告して、笛なしでビルド)、`config.h` の `HAVE_QT_MULTIMEDIA`。autotools は `--enable-sound` (`AC_CHECK_HEADER([QSoundEffect])`)。`AUTORCC` は今 3D の部分でだけ ON (src/CMakeLists.txt:114) なので、3D の外でも有効にする。CI に `qt6-multimedia-dev`、`qtmultimedia5-dev` を足す。Qt6 では、実行時にマルチメディアのバックエンド (FFmpeg または GStreamer のプラグイン) が要ることを `docs/build.md` に書く。
- 設定: `whistle` (オン/オフ)、`whistle_volume` (0〜100)。メニュー (Monitor か View。段階の初めに決める) にオン/オフ、設定ダイアログの Show タブに Sound の群 (タブは増やさない。S4)、コマンドライン。
- 既定のオン/オフは、段階の初めにユーザと決める (競技会の会場で多くのモニタが同時に鳴る懸念がある)。
- Qt Multimedia なしでビルドしたときは、メニューと設定を出さない (または無効にし、理由を出す)。
