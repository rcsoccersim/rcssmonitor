## 1. Goal and scope

Before the official release of rcssmonitor 20.0.0, the following features are added (the version is already 20.0.0-beta.1, but it has not been released. `docs/dev/release.md` §0).

| # | Feature | Kind | Plan |
|---|---|---|---|
| F1 | Choose the color scheme (light/dark), as soccerwindow2 does | Required | This document, §A |
| F2 | Keep the icons as PNG instead of XPM (the same way as soccerwindow2) | Required | [2026-11-22-01_icon-redesign_en.md](2026-11-22-01_icon-redesign_en.md) |
| F3 | Find and start it from the GNOME desktop search | Required | This document, §B |
| F4 | Blow the referee's whistle when the play mode changes | Nice to have | This document, §C |
| F5 | Download an rcg from a given URL and play it. Lists of the logs on GitHub and the archive | Nice to have | [2026-11-22-02_remote-logs_en.md](2026-11-22-02_remote-logs_en.md) |
| F6 | Export what is drawn on the screen as an image sequence or a video | Nice to have | [2026-11-22-03_frame-export_en.md](2026-11-22-03_frame-export_en.md) |

- The plans are split by the size of the features. The three small ones (F1, F3, F4) are in this document, and the three large ones (F2, F5, F6) have their own plans.
- This document also has the overall order and branches, the decisions shared by the features, and the way to the release.

### 2.2 Design decisions across the features (Claude; the user confirms them at the start of each stage)

| # | Content | Reason |
|---|---|---|
| S1 | Qt Multimedia is an optional dependency. The whistle (`QSoundEffect`, Qt5 and Qt6) and the video prototype (`QVideoFrameInput`, Qt 6.8 or later) use it. Without it, the program builds without those features | Same as WebSockets (`ENABLE_WEBSOCKET`). The build on the minimum environments (Qt 5.15, Qt 6.2) is kept |
| S2 | Optional dependencies follow `ENABLE_WEBSOCKET`: in CMake, `option()` + `find_package(... QUIET)` + `#cmakedefine HAVE_*` in `cmake-config.h.in`, and `message(WARNING)` when not found. In autotools, `AC_ARG_ENABLE` + `AC_CHECK_HEADER` + `AC_DEFINE` + `AM_CONDITIONAL` | The existing pattern (WebSockets in `CMakeLists.txt`, `--enable-websocket` in `configure.ac`) |
| S3 | New settings go to `~/.rcssmonitor.conf` (`Options`, QSettings INI). `Options::writeSettings(bool all)` (options.cpp:868) writes the MainWindow and Monitor groups only when `all` is true, so a setting added there is written outside `if ( all )`. But a setting written when the program ends is saved with the value given on the command line too. A setting whose command line value is not saved (the color scheme; U7) is not written at the end, but at once when it is chosen from the menu | Prevents added settings from not being saved |
| S4 | Avoid adding tabs to the config dialog. If one is added, also fix the tab lists in `test_config_dialog.cpp` (lines 287, 417) | The tests pin the tab list |
| S5 | When running it to try, start it with `HOME=$(mktemp -d)` so that the user's `~/.rcssmonitor.conf` is not rewritten | Same as §0.1 of the 3D view plan |
| S6 | The CI (`.github/workflows/ci.yml`) and `docs/build.md` (the table of packages, the CMake and configure options) are updated on the branch of the feature that adds a dependency | Added dependencies are not left out of the documents and the CI |

## §A Color scheme (light/dark)

### A.1 Current state (develop 5affd90)

- There is no way to choose the color scheme. View > Window Style only chooses the Qt style (QStyle).
- The chosen style is not saved: `MainWindow::changeStyle()` (main_window.cpp:2436) does not update `M_window_style`. Its default `"plastique"` does not exist in Qt5/Qt6, so `QApplication::setStyle( M_window_style )` at startup (line 167) fails and the platform style stays.
- The toolbar icons are XPMs or shapes drawn by code, recolored with `QPalette::ButtonText` (`tintIcon` in `src/tool_icon.cpp`, `src/toolbar_icons.cpp`). When the palette changes, `MainWindow::updateToolIcons()` (line 1470) recolors them.
- The drawing of the field (2D and 3D) does not depend on QPalette. The colors are the `Options` settings (the Color tab) or colors written in the code.
- What depends on the palette: the background of the view stack (`M_view_stack`) is set to black (line 1103; `test_view_switch.cpp` checks it), the red of an error in the cycle field (lines 1588-1599), the red of an out-of-range number in the config dialog (`markNumber`, config_dialog.cpp:1731), the color of an error in the figure pack credits (`color: #c03030;`, line 2725), and the tooltip marker (`tooltip_marker.cpp`, `WindowText`).

### A.2 Approach (port soccerwindow2's implementation)

Same as soccerwindow2 (`../../rctools/soccerwindow2`; commits 7e87a9c, 8a15c38; Phase 5 of its plan `docs/plan/2026-11-19_qt6-cmake-migration.md`).

- `src/ui_palette.{h,cpp}` (new): `UIPalette::light()` and `UIPalette::dark()`, built by hand with the same colors as the Fusion palette of Qt 6.5 or later (`qt_fusionPalette()`). They look the same with Qt5 and Qt6. From `soccerwindow2/src/qt/ui_palette.cpp`.
- `src/ui_style.{h,cpp}` (new): a `QProxyStyle` that draws the checked toolbar buttons as a translucent rounded rectangle of the highlight color, because the checked state is hard to see in the dark scheme. From `soccerwindow2/src/qt/ui_style.cpp`.
- `Options`: `ui_color_scheme` = `system` | `light` | `dark` (default `system`). Command line `--ui-color-scheme {system,light,dark}`. Saved only when chosen from the menu; a value given on the command line is not saved (same as soccerwindow2). It is written to `ui_color_scheme` of `[MainWindow]` at once when chosen from the menu (U7; `Options::writeUIColorScheme()`). `Options::writeSettings` writes the default only when it makes the settings file (`all`).
- Menu: View > UI Color Scheme > System / Light / Dark. An exclusive `QActionGroup`, next to Window Style.
- Applying: `QApplication::setPalette()`. System is the `QApplication::palette()` taken when MainWindow is created (so that tests can fake a dark desktop). After the Qt style is changed, the scheme is applied again (because `setStyle` resets the palette).
- To review in the dark scheme: what depends on the palette in A.1, the player type dialog, the list of the Color tab of the config dialog. The colors of the field (2D and 3D) and the 3D HUD are not changed (same as soccerwindow2).
- To check: with Qt 6.5 or later and System chosen, whether it follows a change of the desktop's scheme while running. If not, decide with the user how far to support it. → Cannot be checked in this environment (Qt 6.4.2) (A.6).
- The window style not being saved (A.1) is fixed too (U8): the default is empty (the platform's), the style chosen from the menu goes into `M_window_style`, and it is saved when the window closes (`MainWindow::writeSettings`). When no style has the saved name (e.g. `plastique`, written by older versions), the platform's style is used and the name is cleared.

## §B Desktop (find and start it from GNOME)

### B.1 Current state (develop 5affd90)

- The default installation prefix of CMake is `~/.local` (PR #69). From `data/rcssmonitor.desktop.in`, a desktop entry with the absolute path of the installed `bin` in `TryExec` and `Exec` is made and installed in `share/applications` (CMakeLists.txt:148-166). Only the 48×48 `icons/rcssmonitor.png` is installed as the application icon, in `share/icons/hicolor/48x48/apps` (line 167).
- The user's environment has `~/.local/share/applications/rcssmonitor.desktop` and the 48×48 icon installed.
- The desktop entry has no `GenericName`, `Keywords` or `StartupWMClass`. It is not found by "robocup" or "soccer". `Categories=Development;`.
- `QGuiApplication::setDesktopFileName()` is not called (`src/main.cpp` only calls `setApplicationName` and `setApplicationVersion`). There is no guarantee that the Wayland app_id is tied to the desktop entry, so the icon in the dash and the grouping of the windows may be wrong.
- The window icon is the 48×48 XPM (`main_window.cpp:105`).
- Autotools installs neither the desktop entry nor the icon (`docs/build.md`).
- `cmake/DistCheck.cmake` checks the installed desktop entry (`TryExec`/`Exec`, `desktop-file-validate`) and the 48×48 icon.

- Checked (Ubuntu 24.04):
  - The CMake builds with Qt 6.4.2 and Qt 5.15.13 had no warnings, and the 59 tests of `ctest` (including the new `check_desktop_entry`) passed.
  - Failures of `check_desktop_entry.sh`: a wrong `--connect`, a wrong icon name, a missing `Actions`, a wrong `StartupWMClass`, a `Type` outside the standard, and a wrong `TryExec` all failed. With a PATH without `desktop-file-validate`, it gave 77 (1 if broken).

- The difference of size between the dash and the terminal (pointed out by the user, 2026-11-23):
  - Started from the dash, the text of the menus was smaller than when started from the terminal. Cause: in the terminal, `QT_QPA_PLATFORM=xcb` of `~/.bashrc` applies, and Qt6 draws on X11 (XWayland) at the scale 1.292 from `Xft.dpi` 125. ## §C Referee's whistle

### C.1 Current state, and where to catch the moment to blow it

- There is nothing that plays sounds. Qt Multimedia is not used anywhere, and the build does not look for it. This environment (Ubuntu 24.04, Qt 6.4.2) does not have `qt6-multimedia-dev` installed (the package exists).
- When the shown frame changes, `LogPlayer::indexUpdated(current, max)` is emitted (log_player.cpp): on timer playback, stepping, moves by the slider or jumps, live (`showLive`, line 444), delayed live (`showDelayedLive`, line 578), and the move to the first frame when a log is opened.
- The play mode of frame i is `DispHolder::dispCont()[i]->pmode_` (`rcss::rcg::PlayMode`, `rcss/rcg/types.h:60`). `DispHolder::playmode()` is the last mode read, not the shown one.
- Where the index moves without a signal: `LogPlayer::setLiveMode()` (line 478), `DispHolder::trimLiveFrames()` (disp_holder.cpp:261; drops old frames and shifts the indices), and `clear()`.
- Connecting to `DispHolder::handlePlayMode` is wrong: it is also called while reading a whole log, and in live mode at the time of receipt, not of display.

### C.2 When to blow it

- Connect to `LogPlayer::indexUpdated` and compare the play mode of the shown frame with the mode seen before.
- Log playback: blow it only when it advanced by one (`current == prev + 1`; timer playback and stepping forward). On jumps, the slider, stepping back and going to the first frame, do not blow it; only update the remembered mode.
- Live and delayed live: one update may advance several frames, so look at the frames in (prev, current], and if there is a transition, blow it once (the strongest whistle if there are several).
- When a log is opened (around `M_disp_holder.clear()` at main_window.cpp:1861), on connecting (line 1983), and after `setLiveMode()` and `trimLiveFrames()`, forget the remembered mode (or remember it by cycle instead of index).
- So that whistles do not overlap in fast playback, stop the whistle being played before playing the next one.
- In live mode, the 3D view draws up to 2 cycles late (`LiveClock`). The whistle may sound a little before the 3D view shows the moment; this is accepted and recorded.

### C.3 Play modes and whistles (proposal; decided with the user at the start of the stage)

#### C.3.1 The whistle in real football (the guidelines of the Laws of the Game)

The Whistle part of IFAB's "Practical guidelines for match officials" in the Laws of the Game (https://theifab.com/laws/latest/guidelines/body-language-communication-and-whistle , checked on 2026-11-22):

| The whistle is needed | The whistle is not needed |
|---|---|
| To start play (first and second half of normal play and extra time), after a goal (the kick-off) | To stop play for a clear goal kick, corner kick, throw-in or goal |
| To stop play: for a free kick or penalty kick, if the match is suspended or abandoned, at the end of each half | To restart play from most free kicks, and a goal kick, corner kick, throw-in or dropped ball |
| To restart play for free kicks when the appropriate distance (9.15 m) is required, and penalty kicks | |
| To restart play after it has been stopped for a caution or sending-off, injury, or substitution | |

- It also says that a whistle used too frequently or unnecessarily will have less impact when it is needed.
- The number of whistles at the end of each half is not in the Laws (a custom).

#### C.3.2 What rcssserver does (`../rcssserver/src/referee.cpp`)

- On fouls (`foul_*`), offsides, back passes, free kick faults, catch faults and illegal defense, it stays in that play mode for 30 cycles (3 seconds; `AFTER_FOUL_WAIT`, `AFTER_OFFSIDE_WAIT`, etc.), moves the defending players away from the ball in the last 5 cycles (`CLEAR_PLAYER_TIME`, `clearPlayersFromBall`), and then changes to `free_kick_*` or `indirect_free_kick_*`.
- So after a foul there are two clear points: "stop" (the foul mode) and "restart after making the players keep the distance" (the free kick mode). They correspond to "stop play for a free kick" and "restart play for free kicks when the appropriate distance is required" of the guidelines (both need the whistle).
- Throw-ins, corner kicks, goal kicks, etc. change directly from `play_on` to their mode, and the players are moved away from the ball when the mode changes (`FreeKickRef::playModeChange`). There are no separate points of stopping and restarting.
- `free_kick_*` after the goalkeeper's catch also changes directly from `play_on` (a scene with neither a stopping nor a restarting whistle).
- A dropped ball is `drop_ball` followed at once by `play_on` (`Referee::awardDropBall`; except in the penalty shootout).

#### C.3.3 Proposal (2026-11-22; waiting for the user's confirmation)

On free kicks after fouls, a short whistle for the restart is blown (two whistles with the one at the foul). As in C.3.2, the server restarts after making the players keep the distance, so this matches the guidelines of real football. The previous mode tells them apart from free kicks after a catch.

| Transition | Whistle | The guidelines |
|---|---|---|
| → `kick_off_l/r` | Short | Start, after a goal (needed) |
| → `foul_charge_l/r`, `foul_push_l/r`, `foul_multiple_attack_l/r`, `foul_ballout_l/r`, `offside_l/r`, `back_pass_l/r`, `free_kick_fault_l/r`, `catch_fault_l/r`, `illegal_defense_l/r` | Short | Stop for a free kick (needed) |
| A mode of the row above → `free_kick_l/r`, `indirect_free_kick_l/r` | Short (restart) | Restart of a free kick with the distance required (needed) |
| → `penalty_ready_l/r` (the signal that the penalty kick may be taken) | Short | Restart for a penalty kick (needed) |
| → `goal_l/r` | Long (for effect) | Not needed for a clear goal. Whether to blow it is decided at the start of the stage |
| → `first_half_over` | Long, twice | End of a half (needed; the number is a custom) |
| → `time_over` | Long, three times (end of the game) | Same as above |
| `play_on` → `free_kick_l/r` (after a catch), → `kick_in_l/r`, `corner_kick_l/r`, `goal_kick_l/r`, `drop_ball`, `play_on`, `before_kick_off`, `pause`, `human_judge`, `penalty_kick_l/r`, `penalty_setup_l/r`, `penalty_taken_l/r`, `penalty_miss_l/r`, `penalty_score_l/r` | None | Not needed to stop or restart |

- Changed from the previous proposal: a short whistle was added for the restart of free kicks after fouls. `drop_ball` gets no whistle (no whistle is needed to restart from a dropped ball; in rcssserver the ball is dropped without stopping, e.g. when a set play is not taken in time).
- Whether to blow the goal whistle, and whether the restart whistles can be turned off in the settings, are decided at the start of the stage.
- The order of the transitions in extra time and the penalty shootout is checked in rcssserver at the start of the stage.

### C.4 Implementation

- `src/whistle_rules.{h,cpp}` (new): a pure function that returns the kind of whistle (none, short, long, long ×2, long ×3) from the previous and the next modes. Unit tests check the table.
- `src/whistle.{h,cpp}` (new): the watching of C.2 and blowing the whistle. The part that plays the sound is an interface, replaced by a fake in the tests. With Qt Multimedia, it plays by `QSoundEffect`.
- Sounds: synthesized by `tools/make_whistle.py` (new; only the Python standard library: `wave`, `math`, `random`). A tone of about 3 kHz, modulated finely as the ball in a whistle does. The random seed is fixed so that the same WAV can be made again. `resources/sounds/whistle_short.wav` and `whistle_long.wav` are made, committed, and embedded by `resources/sounds/sounds.qrc`. The long whistle twice and three times is repeated by the player. Rough size: 44.1 kHz, 16 bits, mono, a few hundred KB or less in total.
- Dependency: the CMake option `ENABLE_SOUND` (default ON; without Qt Multimedia, a warning and a build without the whistle), `HAVE_QT_MULTIMEDIA` in `config.h`. Autotools: `--enable-sound` (`AC_CHECK_HEADER([QSoundEffect])`). `AUTORCC` is now ON only in the 3D part (src/CMakeLists.txt:114), so enable it outside it too. Add `qt6-multimedia-dev` and `qtmultimedia5-dev` to the CI. Write in `docs/build.md` that with Qt6 a multimedia backend (the FFmpeg or GStreamer plugin) is needed at run time.
- Settings: `whistle` (on/off) and `whistle_volume` (0-100). On/off in a menu (Monitor or View; decided at the start of the stage), a Sound group in the Show tab of the config dialog (no new tab; S4), and the command line.
- Whether it is on by default is decided with the user at the start of the stage (concern: many monitors blowing at once at a competition venue).
- When built without Qt Multimedia, the menu and the settings are not shown (or disabled with the reason shown).
